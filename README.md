# Google Dino / D.I.N.O.

**Google Dino** — это реализация классической браузерной игры Chrome Dino на цифровой логике в **Logisim 2.7.1**. В проекте игровая логика, отрисовка, обработка клавиатуры, счётчики, таймер, генерация препятствий и таблица рекордов собраны из логических схем. Для обработки таблицы результатов используется процессор **CdM-8** и программа на ассемблере.

Проект показывает, как из базовых цифровых компонентов можно собрать полноценную интерактивную игру: с персонажем, препятствиями, прыжком, приседанием, сменой сложности, таймером, очками и сохранением результатов.

---

## Основные возможности

- Управление динозавром: прыжок, приседание, пауза и перезапуск.
- Несколько типов препятствий: маленький кактус, большой кактус, широкий кактус и птица.
- Случайная генерация препятствий с ограничением по расстоянию между объектами.
- Птицы появляются только начиная со второго уровня и могут лететь на разной высоте.
- Анимация птицы через чередование двух состояний крыльев.
- Физика прыжка на основе изменения скорости и координаты по тактам.
- Проверка столкновений на уровне пикселей через логические операции.
- Подсчёт очков в BCD-формате.
- Таймер игры в формате `MM:SS`.
- Уровни сложности, которые растут по мере набора очков.
- Увеличение скорости объектов и прыжка с ростом уровня.
- Ввод никнейма до 3 символов.
- Таблица результатов, сортируемая программой на процессоре CdM-8.

## Требования

Для запуска проекта нужны:

- **Logisim 2.7.1**;
- **Java Runtime Environment** для запуска Logisim;
- файлы проекта из данного репозитория.

Проект создан в формате Logisim `source="2.7.1"`, поэтому лучше открывать его именно в классическом Logisim 2.7.1 или совместимой версии.

## Быстрый запуск

1. Откройте Logisim.
2. Выберите `File -> Open`.
3. Откройте основной файл проекта:

```text
GoogleDino_project.circ
```

4. Перейдите в режим симуляции через инструмент `Poke Tool` / «рука».
5. Включите такты:

```text
Simulate -> Ticks Enabled
```

или используйте горячую клавишу:

```text
Ctrl + K
```

6. Установите подходящую частоту тактового генератора. Для стабильной работы удобно использовать частоты около `512 Hz` или `1024 Hz`.
7. Введите никнейм на клавиатуре таблицы результатов.
8. Нажмите `Enter`, чтобы подтвердить никнейм.
9. Снимите паузу на клавиатуре игрового дисплея.
10. Начинайте игру.

## Управление

### Управление динозавром

| Клавиша | Действие |
|---|---|
| `Space`, `W`, `↑` | Прыжок |
| `S`, `↓` | Приседание / выход из приседания |
| `P` | Пауза |
| `R` | Перезапуск игры |

Приседание работает как переключатель: первое нажатие включает приседание, повторное нажатие возвращает динозавра в обычное состояние. Повторный прыжок во время уже выполняющегося прыжка игнорируется.

### Ввод никнейма

| Клавиша | Действие |
|---|---|
| Буквы | Ввод символов никнейма |
| `Enter` | Подтвердить никнейм |
| `Clear` | Очистить поле ввода |

Никнейм ограничен четырьмя символами. После подтверждения никнейма процессор получает данные и открывает доступ к игровому процессу.

## Главная архитектура

Основная схема находится в файле `GoogleDino_project.circ`. Внутри неё ключевыми являются две схемы:

- `interface` — внешний интерфейс игры, то есть дисплеи, клавиатуры, индикаторы очков, таймер и таблица результатов;
- `main` — центральная логика игры, которая связывает движение препятствий, динозавра, счётчики, уровни, таймер, процессор и вывод на экран.

Общая логика работы такая:

1. Пользователь вводит никнейм.
2. Схема `username` подготавливает символы для передачи в процессор.
3. После подтверждения имени игра разблокируется.
4. `random_spawn` решает, когда создать новое препятствие.
5. `obstacles` создаёт кактусы, а `birds` создаёт птиц.
6. `shiftreg` двигает препятствия по экрану.
7. `keyboard_handler` обрабатывает клавиши управления.
8. `dino_jump` рассчитывает вертикальное положение динозавра.
9. `dino` отрисовывает персонажа и проверяет столкновения.
10. `counter`, `timer` и `level` обновляют очки, время и сложность.
11. При проигрыше результат передаётся в CdM-8.
12. CdM-8 сортирует таблицу результатов и отдаёт данные на вывод.

## Основные схемы проекта

### `interface`

`interface` — это схема, с которой напрямую взаимодействует пользователь. Она объединяет игровое поле, клавиатуры и индикаторы.

В интерфейсе используются:

- дисплей из четырёх матриц `32x32` для игрового поля;
- индикаторы для очков;
- матрица для отображения текущего уровня;
- индикаторы таймера `MM:SS`;
- клавиатура управления динозавром;
- клавиатура для ввода никнейма;
- кнопки `Enter` и `Clear`;
- дисплей таблицы рекордов.

### `main`

`main` — центральная схема игры. Она собирает все крупные подсистемы в одну рабочую логику.

Внутри `main` можно выделить четыре блока:

**Блок отрисовки и управления персонажем.** Здесь работают схемы `random_spawn`, `obstacles`, `birds`, `shiftreg`, `keyboard_handler`, `dino_jump`, `dino`, `pause_screen`, `gameover_screen`. Они отвечают за генерацию препятствий, движение объектов, обработку клавиатуры, прыжок, приседание, коллизии и отображение надписей.

**Блок скорости.** Схемы `common_speed` и `dino_speed` выбирают частоту движения объектов и прыжка в зависимости от уровня сложности.

**Блок счётчиков.** Сюда относятся `counter`, `timer`, `new_level` и `cmp`. Они считают очки, время, уровень и формируют сигнал повышения сложности.

**Блок процессора.** Сюда входят `username`, `cdm8` и схемы вывода таблицы результатов. Этот блок принимает никнейм и очки, сортирует результаты и обновляет таблицу.

### `keyboard_handler`

Схема обрабатывает нажатия клавиш. Она распознаёт команды прыжка, приседания, паузы и перезапуска. Также учитывается состояние динозавра: если он уже находится в прыжке, новый прыжок не запускается.

### `dino_jump`

Схема отвечает за вертикальное движение персонажа. Прыжок реализован через обновление скорости и координаты по тактам:

```text
v = v0 - g · t
s = s0 + v · t
```

В проекте используется простая дискретная модель: начальная скорость `v0 = 6`, ускорение свободного падения `g = 1`. Прыжок заканчивается, когда вертикальная координата возвращается к нулю.

### `dino`

Схема `dino` отвечает за отображение персонажа и проверку столкновений.

Она выполняет три задачи:

1. выбирает спрайт динозавра в зависимости от состояния: обычное положение или приседание;
2. сдвигает спрайт по вертикали во время прыжка;
3. проверяет коллизию между динозавром и препятствиями.

Столкновение определяется логически: если пиксели динозавра и препятствия пересекаются, операция `AND` даёт ненулевой результат. После этого поднимается сигнал `collision`, и игра переходит в состояние проигрыша.

### `random_spawn`

`random_spawn` отвечает за случайное появление препятствий. Схема получает текущий уровень и на его основе регулирует расстояние между препятствиями.

Особенности:

- кактусы могут появляться с начала игры;
- птицы появляются только со второго уровня;
- шанс появления птицы составляет примерно `12.5%`;
- новое препятствие не создаётся слишком близко к предыдущему.

### `obstacles`

Схема выбирает один из вариантов кактуса и передаёт его на отрисовку по столбцам. Внутри используются отдельные схемы для маленького, большого и широкого кактуса.

Пока текущее препятствие не закончило отрисовку, новое препятствие не генерируется. Это защищает игровое поле от наложения объектов в момент генерации.

### `birds`

`birds` генерирует птиц. Птица отличается от кактусов тем, что имеет анимацию и может лететь на разной высоте.

В проекте есть два состояния птицы:

- `bird-wings-up` — крылья подняты;
- `bird-wings-down` — крылья опущены.

Основная схема чередует эти состояния, создавая эффект полёта. Высота полёта выбирается случайно: птица может лететь высоко, на уровне прыжка или на уровне, где от неё нужно уклоняться приседанием.

### `shiftreg`

`shiftreg` — одна из ключевых схем отрисовки. По сути, это модифицированный 32-битный сдвиговый регистр.

Он нужен для того, чтобы:

- хранить столбцы изображения препятствий;
- сдвигать объекты по игровому полю;
- объединять несколько слоёв через логическое `OR`;
- очищать поле при перезапуске;
- скрывать внутреннее значение при необходимости, например для анимации птиц.

Такая схема позволяет двигать объекты по экрану как последовательность вертикальных столбцов.

### `counter`

`counter` считает очки игрока. Счёт хранится в BCD-формате, поэтому каждая цифра обрабатывается отдельно.

Внутри используются:

- `bcd_counter` — счётчик одной десятичной цифры;
- `bcd_add` — BCD-сумматор;
- дополнительные счётчики для десятков, сотен и тысяч;
- `number_sen` — разделение 16-битного счёта на два 8-битных значения для передачи в процессор.

### `timer`

`timer` считает время игры в формате `MM:SS`. Для этого используются счётчики до 10 и до 6:

- `10-counter` считает единицы секунд и единицы минут;
- `6-counter` ограничивает десятки секунд и десятки минут.

Таймер останавливается при паузе или завершении игры и сбрасывается при рестарте.

### `new_level` и `cmp`

Эти схемы отвечают за повышение уровня сложности. Уровень меняется при достижении определённых значений очков.

В проекте используются пороги:

```text
200 -> 800 -> 1400 -> 2000
```

После повышения уровня меняется скорость движения препятствий и скорость прыжка динозавра.

### `common_speed` и `dino_speed`

Эти схемы выбирают тактовую частоту в зависимости от текущего уровня.

- `common_speed` управляет скоростью движения препятствий;
- `dino_speed` управляет скоростью прыжка динозавра.

Разделение важно, потому что при ускорении игры нужно синхронно менять не только движение препятствий, но и поведение персонажа.

### `pause_screen`, `gameover_screen`, `invertor`

`pause_screen` и `gameover_screen` накладывают текстовые надписи поверх игрового поля. Для лучшей читаемости используется логика `XOR`, чтобы текст был заметен даже на фоне объектов.

### `username`

`username` обрабатывает ввод никнейма. Схема принимает символы с клавиатуры, поддерживает очистку и подтверждение ввода. После подтверждения данные передаются процессору CdM-8.

### `cdm8` и `last_sort.asm`

Процессор CdM-8 используется для работы с таблицей результатов. Программа `insertion_Sort.asm` реализует сортировку результатов и обновление таблицы.

Общий сценарий работы:

1. процессор ожидает ввод никнейма;
2. после завершения игры получает очки игрока;
3. сохраняет никнейм и результат;
4. сортирует результаты сортировкой вставками;
5. выводит отсортированные данные для таблицы рекордов;
6. возвращается в режим ожидания нового никнейма.

Файл `insertion_Sort.img` — это скомпилированный образ программы, который используется процессором в схеме.

## Логика игрового цикла

Игровой цикл можно описать так:

```text
Ввод никнейма
      ↓
Разблокировка игры
      ↓
Генерация препятствий
      ↓
Сдвиг препятствий по экрану
      ↓
Обработка клавиатуры
      ↓
Прыжок / приседание динозавра
      ↓
Проверка столкновения
      ↓
Обновление очков, таймера и уровня
      ↓
Если столкновения нет — цикл продолжается
Если столкновение есть — game over
      ↓
Передача результата в CdM-8
      ↓
Сортировка и обновление таблицы рекордов
```

## Что важно понимать в реализации

Главная идея проекта — представить экран как набор вертикальных столбцов. Каждый объект кодируется набором 32-битных значений, где каждый бит отвечает за пиксель в столбце. Чтобы объект двигался, его столбцы последовательно проходят через сдвиговые регистры.

Отрисовка нескольких объектов выполняется через логическое `OR`: если хотя бы один слой содержит пиксель, он появляется на итоговом игровом поле.

Коллизии проверяются через логическое `AND`: если пиксель динозавра и пиксель препятствия находятся в одной позиции, значит произошло столкновение.

Очки и время реализованы не как программные переменные, а как цифровые счётчики. Это делает проект хорошим примером того, как привычная игровая логика может быть перенесена в аппаратное мышление.
